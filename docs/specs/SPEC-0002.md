# SPEC-0002 — Estoque de produtos: quantidade atualizada na comanda e modo de estoque explícito

- **Status**: implementada (2026-10-05; tasks no índice em README.md)
- **Criada em**: 2026-10-04
- **Origem**: anotações do responsável (2026-10-04): "Ao adicionar um produto na comanda ele diminui no estoque, não deixa passar dessa quantidade mesmo adicionando duas vezes (excelente), mas o select não muda a quantidade." e "Não gostei de como ficou essa parte de (estoque vazio = sem controle), prefiro uma checkbox ou uma frase intuitiva de registrar quantidade ou estoque livre."
- **Módulo**: `web`

## Contexto

- **Select desatualizado (bug).** A tela de detalhe da comanda (`web/src/app/(app)/comandas/[id]/order-detail-screen.tsx`) carrega serviços e produtos **uma vez**, ao abrir, e mostra `· estoque N` em cada produto do select. Depois de adicionar ou remover um item, ela recarrega a comanda (`reload()`), mas não a lista de produtos. O servidor está certo: a baixa é atômica e nunca deixa o estoque negativo ([ADR-0011](../decisions/0011-comandas-estoque-e-duplicidade.md)). O número exibido é que fica velho.
- **"Vazio = sem controle".** No cadastro de produto (`web/src/app/(app)/produtos/products-screen.tsx`), o campo se chama "Estoque (vazio = sem controle)", e a tabela mostra "Sem controle". A regra (`stock_quantity` nulo = estoque ilimitado) só fica clara para quem lê o rótulo com atenção.

## Objetivo

Quem monta a comanda vê sempre o estoque real. Quem cadastra um produto escolhe, com palavras claras, se quer controlar a quantidade ou não.

## Requisitos

### RF-1 — Estoque do select sempre atualizado

Depois de adicionar ou remover um item na comanda, a lista de produtos é recarregada e o select mostra o estoque atual. Produto com controle de estoque e saldo zero aparece **desabilitado**, com a indicação "sem estoque".

**Aceite:** um produto com estoque 3. Adicionar 2 → o select mostra `estoque 1` sem recarregar a página. Adicionar 1 → o produto aparece desabilitado, "sem estoque". Remover o item → volta a `estoque 1`.

### RF-2 — Escolha explícita do modo de estoque no cadastro

O formulário de produto troca o campo "Estoque (vazio = sem controle)" por uma escolha entre duas opções, com estes textos:

- **Registrar quantidade**: mostra o campo de quantidade, obrigatório, inteiro ≥ 0.
- **Estoque livre**: esconde o campo de quantidade; o produto pode ser vendido sem limite.

O controle pode ser radio, segmentado ou checkbox, desde que os dois textos apareçam. Em produto novo, o padrão é **Registrar quantidade**. A tabela de produtos mostra "Livre" no lugar de "Sem controle".

**Aceite:** criar produto com "Estoque livre" grava `stockQuantity: null`; com "Registrar quantidade" e o campo vazio, a validação recusa com mensagem em pt-BR; editar um produto existente abre na opção certa.

### RF-3 — Contrato da API inalterado

O modelo de dados não muda: `stockQuantity: null` continua significando estoque livre. RF-2 é só de interface.

**Aceite:** os testes de API de produtos e de comandas existentes continuam passando sem alteração.

## Fora de escopo

- Movimentação de estoque (entrada de mercadoria, histórico, inventário).
- Alerta de estoque baixo.
